# 基本設計書からの変更・決定事項

基本設計書(企画・基本設計書:ポーズ選択型 AIフォトブース)に対する、実装時の決定事項。

## 2026-10-18

### カメラ取得
- カメラ映像は **Unity 側(WebCamTexture)** で取得し、判定・切り抜き時のみ JPEG を Python へ送る。
- 理由:カメラは同時に1プロセスしか開けない/表示と判定・合成のフレームが同一になる/Unity内推論への差し替え(§4-4)で入力経路が変わらない。

### 通信(§4-1 変更)
- UDP/WebSocket ではなく **ローカル HTTP(FastAPI + UnityWebRequest)**。判定は要求→応答の1往復のみのため。

### ミラー・左右(§13 決定)
- プレビューも最終写真も **鏡像**。判定も鏡像画像上で行う。
- 左右は「画面の左右」で定義する(解剖学的な左右は使わない)。
  - 例:`raise_screen_right` = 画面右側の手を上げる = 撮影者の右手 = タレントの左手。

### 判定範囲:上半身のみ(§3-1, §5-2, §5-3 変更)
- 全身撮影には約2m以上離れる必要があるため、**腰から上** の撮影・判定に変更。
- 使用関節:肩・肘・手首(腰は使える時だけ補助)。
- 特徴量:上腕・前腕(左右4本)の単位方向ベクトル + 肩幅で正規化した肩→手首の相対位置。
- 正規化:両肩の中点を原点、肩幅でスケール。
- ガイド①:頭・両肩・腰が枠内に入る位置(目安:C200 広角95°で約1.2〜1.5m)。
- フォールバック:肩・肘・手首の visibility が低い場合もデフォルトポーズ。

### ポーズ表現
- ポーズは AnimationClip ではなく、**腕の骨の向き(画面座標系の方向ベクトル)** で定義する(`PoseSync/Assets/StreamingAssets/poses.json`)。
  - Unity はこの向きに Humanoid の腕の骨を回転させて表示、Python は同じファイルからテンプレートを作る。
  - モデルを差し替えても定義はそのまま使える。テンプレの実測平均への差し替え(§5-4)はデータ差し替えで対応。
- 待機モーションは、まず手続き的な「わくわく」モーション(上下に弾む+腕振り)で代用。Mixamo 等のクリップへ差し替え可能。

### 3Dモデル
- VRM(UniVRM、OpenUPM 経由で導入)。MMD モデルは Blender + mmd_tools で VRM/FBX に変換して使う。

### ポーズ構成の変更(2026-10-18):6種 → 4種+デフォルト
タレントは撮影者のポーズを真似するのではなく、**対になるポーズで応える**。

| id | key | 撮影者(判定テンプレート、画面座標) | タレントの応答 |
|---|---|---|---|
| 0 | heart_half | 片手が体を横切り、画面右側(タレント側)の胸の高さ。前腕は横向き | 左手(画面右の腕)で体を横切り、画面左側にハートの片割れ |
| 1 | big_heart | 両腕を画面右側へ伸ばし上下で弧。肩はタレント側へ傾く | 両腕を画面左側へ、上の腕は頭上で弧。体は撮影者側へ傾く |
| 2 | double_peace | 両手首が肩より上、前腕が縦 | 両手ピース、撮影者側へ少し傾く |
| 3 | peace | 片手だけ上げて前腕が縦(左右どちらでも:mirror) | 画面左の手(撮影者に近い側)でピース |
| -1 | default | どれにも似ていない | おまかせポーズ |

- ハートは「どちらの手か」ではなく「画面のどちら側か」で定義する。ミラー表示なので、撮影者が実際に使うのは左手(タレントに向かって手を伸ばす)。
- ハートが画面左側(タレントと反対側)に作られた場合はハートとして扱わない。
- タレントの位置は固定。ハートを合わせるための誘導はせず、見本ポーズの切り替え中に撮影者が自分で位置を合わせる想定。
- 指の形(ピースかどうか等)は判定しない。腕の向きと肩の傾きのみ。
- poses.json v2:`talent`(腕・指の形・手首の向き・背骨の傾き)と `user_templates`(判定用、複数可、`mirror` で左右反転版を自動追加)を分離。
- 指は Humanoid の筋肉値(Stretched: +1=伸ばす/-1=曲げる)で制御。プリセット relaxed / peace / heart / open / fist。
- ハートの片割れは、肘を体の前に出して前腕が胸の前を通る形(体へのめり込み対策)。

### ポーズ判定(Python、2026-10-18 / 2日目)
- 構成:`server/posesync/` に `features.py`(特徴量)/ `matcher.py`(テンプレート比較・フォールバック・多数決)/ `estimator.py`(MediaPipe)。
- 特徴量:上腕・前腕4本の 2D 単位方向 + 肩幅正規化した手首位置 + 肩ラインの傾き。奥行き方向を向いた骨は信頼度で重みを下げる。
- 距離:度に揃えた**重み付き RMS**(平均だと片手ポーズ同士の差が薄まるため)。ハート↔ピースの距離が平均 25.1 → RMS 37.5 に改善。
- フォールバック:最小距離 > 30(初期値)、または肩・肘・手首の visibility < 0.5、または人物なし。閾値は検証データで調整する。
- テンプレート間距離表:`docs/distance_table.md`(`tools/distance_table.py` で再生成)。
- アニメ調のプレビュー画像は MediaPipe でほぼ検出できない(実写向けモデルのため)。テンプレートはモデル定義から直接作り、検証は実カメラで行う。
- 検証ツール:`tools/live_judge.py`(リアルタイム判定表示、1〜4/0 キーで正解ラベル付きサンプルを `data/samples/*.jsonl` に記録)。

### 判定の調整(2026-10-21、自分のサンプル46件)
- 結果の詳細:`docs/validation.md`(`tools/analyze_samples.py` で再生成。記録済みの骨格から現在のロジックで再計算する)。
- 初期設定(閾値30、肩・肘・手首の visibility < 0.5 でフォールバック)では全体 **71.7%**。ハートは 8回中1回しか当たらなかった。
  - 原因:体の前を横切る腕は MediaPipe の visibility が 0.01〜0.29 まで下がる。関節位置自体はおおむね正しく、ハート
    テンプレまでの距離は 24〜32 と近かったのに、visibility で即フォールバックしていた。
- 変更:visibility によるフォールバックは**両肩のみ**(枠から外れているかの判定)に限定。腕は距離で判断する。閾値 30 → **40**。
- 変更後:全体 **87.0%**(ポーズ 92.9%、どれでもない 77.8%)。ハート 75% / 大きなハート・両手ピース・ピース 100%。
- 残る誤判定:
  - 「どれでもない」のつもりの片手を上げる動き(手を振る等)4件がピース扱い。指を見ていないための仕様上の限界で、タレントがピースで応えるので体験としては許容。
  - ハートが大きなハート / おまかせになったものが各1件。
- 今後:友人のデータを追加して閾値を再確認し、必要ならハートのテンプレートを実測平均に置き換える(§5-4)。
- live_judge の記録に関節ごとの visibility を追加した(古い記録には無いので、集計時は肩が見えていた扱い)。

### Unity↔Python 通信(2026-10-21 / 3日目)
- `server/app.py`(FastAPI):`GET /health`、`POST /judge`(multipart の `frames` に JPEG 複数 → `{pose_id, key, distance, fallback, reason, votes, latency_ms}`)。
  - distance が無限大の時は 999 を返す(Unity の JsonUtility が Infinity を読めないため)。
- Unity:`FrameRecorder` がカウントダウン中に 0.1 秒間隔で 720px のフレームをリングバッファ(5枚)に貯め、
  シャッターの瞬間の1枚を足して直近5枚(約 0.4 秒間)を送る(§13 の未決事項「枚数と時間範囲」の決定)。
- `HttpPoseEstimator`(IPoseEstimator 実装):サーバーに繋がらない時は `DebugPoseEstimator` に自動で切り替え、体験が止まらないようにした。
- 遅延の実測:人物なしの5フレームでサーバー処理 約75ms。人物ありは1フレーム約65ms なので、5フレームで約0.35秒の見込み(Unity からの往復は Play で要確認)。
- 起動手順は `docs/how_to_run.md`。

### 切り抜き・合成(2026-10-22 / 4日目)
- Python `POST /cutout`:撮影した1枚(JPEG)→ 撮影者を切り抜いた PNG(アルファ付き)。人物なしは 422。
  - マスクは姿勢推定と同じ MediaPipe Pose のセグメンテーション(選ばれた1人分)。元画像をガイドにしたガイデッドフィルタで輪郭に沿わせ、smoothstep(0.35〜0.65)で境界を締める。
  - 既知の課題:手に持ったグッズ(ペンライト・うちわ等)は人物マスクに入らない可能性がある。ISegmenter / Segmenter で差し替え可能にしてあるので、必要なら別モデルを試す。
- Unity:シャッター時に切り抜きを判定と**並行**して依頼。タレントのポーズ遷移が終わった次のフレームで `PhotoCompositor` が 1080×1080 に合成する。
  - 重ね順:背景 → 撮影者の影(黒 25%、右下にずらす)→ 撮影者 → タレント。タレントは画面表示と同じ位置・大きさ。
  - 背景:`StreamingAssets/backgrounds/background.png` があればそれを使う。無ければピンク→ラベンダーのグラデーション+水玉を生成。
  - 撮影者にはカメラ映像と同じ明るさ補正(cameraGain)をかけて合成する。
  - 切り抜きに失敗した時は元の写真のままタレントを重ねる(体験は止めない)。
  - 保存先:`data/photos/PoseSync_日時.png`。結果画面には合成した写真をそのまま表示する。
- 確認:PoseSync > Run Flow Probe(テスト用の楕円切り抜きで全ポーズを自動撮影・合成)。実際の切り抜き品質は `server/tools/cutout_check.py`(→ `docs/cutout_check.png`)。
- (2026-10-22 追記)初回の実撮影で切り抜かれなかった原因:判定サーバーが `/cutout` 追加前の版のまま動いていた(404)。HttpSegmenter は 404 の時に「app.py を再起動」と表示するようにした。
- タレントの大きさを 85%(size 1273 / offsetY -400、頭の位置は維持)に変更。

### ユーザーテストの結果と改善(2026-10-23)
- 結果(3名・16回、詳細は `docs/user_test.md`):**意図したポーズが選ばれた割合 92%(12/13)**、撮影まで完了 94%、切り抜き成功 100%、判定の待ち時間 中央値 0.69 秒。
  閾値は 35〜50 で正解率が変わらないため 40 のまま。外れた1回は「うちわを持った自由ポーズ」がハートと判定されたもの。
- 立ち位置で最大 51 秒かかった回があった → **自動開始**:両肩・両肘が枠の中かつ枠の高さの 40〜90% に 1 秒とどまったら撮影へ進む(`StandingDetector` + Python `/detect`)。頭は髪型・フードで検出しにくいので腕で判定。判定できない時は「撮影開始！」ボタンに切り替える。
- 切り抜きで膝から下が抜ける(暗いズボン × 暗い床・椅子)→ 腰→膝→足首の関節位置に沿った帯をマスクに足してから輪郭を整える(`CutoutConfig.leg_prior`)。
- 枠内の「頭」「腰」の文字を削除。立ち位置の案内文を「撮影完了!」と同じ濃いピンク+白縁に。
- 見本ポーズの表示時間 2 秒 → 3 秒。見本中のポーズ名は表示しない。
- (2026-10-23 追記)脚の補強を入れた後、撮影時に判定と切り抜きが 5 秒でタイムアウトした。原因:MediaPipe のマスクが (H, W, 1) で、2D の脚の帯と `np.maximum` すると (1080, 1080, 1080)・約 4.7GB の配列になり、切り抜きが数秒かかって判定もロック待ちになっていた。マスクを必ず 2D にそろえて修正(切り抜き 約 0.22 秒、同時に送った判定 約 0.47 秒)。
- 体験中に判定サーバーが応答しない時は、ランダムなデバッグ判定ではなく「おまかせ」にする(デバッグ判定はサーバー未起動の開発時だけ)。
- (2026-10-23 追記)案内文はすべて同じ見た目(濃いピンク+白縁)に統一。文言を「ポーズを考えて！」「その場でキープ！」に変更し、立ち位置 OK から撮影開始まで(「その場でキープ！」を出す時間)を 1 秒 → 2.5 秒に。
- 切り抜きの改善を検証できるよう、撮影時に元の写真を `data/photos/raw/` に保存(PC 内のみ)。`tools/cutout_compare.py` で方式を並べて比較する:
  A 姿勢推定のマスクのみ / B +脚・手の補強(既定)/ C +DeepLab v3 の人物マスク / D +selfie multiclass のマスク。
  - 手の補強:手首・指の関節の周りだけ、マスクを採用する基準をゆるめる(ハートの親指など細い部分が抜ける対策)。
  - 追加モデルは写っている全員を拾うため、撮影者の関節を囲む範囲だけに限定する。
  - 採用する方式は `app.py --extra-seg deeplab|multiclass` で切り替える(既定は追加モデルなし)。
